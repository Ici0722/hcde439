Assignment 4: Libraries!

For this assignment, I designed and built an interactive servo motor prototype using an Arduino Uno, a pushbutton, a tilt switch, and an SG90 servo motor. The pushbutton and tilt switch act as two digital inputs, while the servo motor acts as the output. The Arduino reads the states of both inputs and changes the servo motor's position accordingly. This project uses the Servo.h library to control the servo motor's angle.

01. Schematic

I created a schematic to plan the connections between the Arduino Uno, pushbutton, tilt switch, and servo motor. The pushbutton is connected to digital pin D2 and GND, while the tilt switch is connected to digital pin D3 and GND. The servo motor's signal wire is connected to digital pin D9. Its power and ground wires are connected to 5V and GND, respectively.

Circuit Connections

Pushbutton: D2 → Button → GND

Tilt Switch: D3 → Tilt Switch → GND

Servo Signal: D9 → Orange/Yellow Wire

Servo Power: 5V → Red Wire

Servo Ground: GND → Brown/Black Wire

Internal Pull-up Resistors

I used INPUT_PULLUP for both the pushbutton and tilt switch. This enables the Arduino's internal pull-up resistors, which keep the input pins HIGH when their switches are open. When a switch closes, the corresponding input pin is connected to GND and reads LOW. Therefore, no external resistors are required for these two input devices.

02. Circuit Implementation

I assembled the circuit using an Arduino Uno, a breadboard, jumper wires, a pushbutton, a tilt switch, and an SG90 servo motor. The pushbutton connects to D2, and the tilt switch connects to D3. Both switches share a common ground through the breadboard's negative power rail. The servo motor receives its control signal from D9 and is connected to the Arduino's 5V and GND pins.

03. Firmware

I programmed the Arduino using the Servo.h library to control the servo motor's position. The digitalRead() function reads the states of the pushbutton and tilt switch. I used if-statements to determine the servo motor's position based on the inputs. Because the circuit uses digitalRead() instead of analogRead(), analog sensor calibration is not required.

Servo Motor Positions

Button Pressed: The servo moves to 180 degrees.

Tilt Switch Activated: When the button is not pressed and the tilt switch is closed, the servo moves to 90 degrees.

Neither Input Activated: The servo returns to 0 degrees.

I selected 0, 90, and 180 degrees to represent three distinct positions, making the motor's movement easy to observe. These values correspond to the requested angular positions of the servo motor.

Choosing the Pin and Delay Values

I selected D2 and D3 for the two digital input devices because they can read HIGH and LOW signals. Pin D9 is used to send the control pulses to the servo motor through the Servo library. The 50-millisecond delay creates a short interval between input readings. This reduces how frequently the program checks the switches while keeping the circuit responsive. The button takes priority if both inputs are activated simultaneously.

Arduino Code


// Include the Servo library.
#include <Servo.h>

// Create a servo object.
Servo myServo;

// Set the button input pin to D2.
const int buttonPin = 2;

// Set the tilt switch input pin to D3.
const int tiltPin = 3;

// Set the servo control pin to D9.
const int servoPin = 9;

// Run setup once when Arduino starts.
void setup() {
  // Enable internal pull-up resistor for button.
  pinMode(buttonPin, INPUT_PULLUP);

  // Enable internal pull-up resistor for tilt switch.
  pinMode(tiltPin, INPUT_PULLUP);

  // Attach the servo motor to pin D9.
  myServo.attach(servoPin);

  // Set the initial servo position to 0 degrees.
  myServo.write(0);
}

// Repeat the main program continuously.
void loop() {
  // Read the current button state.
  int buttonState = digitalRead(buttonPin);

  // Read the current tilt switch state.
  int tiltState = digitalRead(tiltPin);

  // Check whether the button is pressed.
  if (buttonState == LOW) {
    // Move the servo to 180 degrees.
    myServo.write(180);
  }

  // Check whether the tilt switch is activated.
  else if (tiltState == LOW) {
    // Move the servo to 90 degrees.
    myServo.write(90);
  }

  // Handle the condition where both inputs are inactive.
  else {
    // Return the servo to 0 degrees.
    myServo.write(0);
  }

  // Wait 50 milliseconds before checking again.
  delay(50);
}

04. Final Result

The final prototype uses a pushbutton and a tilt switch to control the angular position of a servo motor. When the button is pressed, the servo rotates to 180 degrees. When the tilt switch is activated and the button is not pressed, the servo moves to 90 degrees. When neither input is activated, the servo returns to 0 degrees. This demonstrates how the Arduino can interpret multiple digital inputs and control a physical output using a library.

Q2. Addressing Occasional Erroneous Readings

If an input device produces an incorrect reading approximately 1% of the time, one possible solution is to use a median filter. Instead of using a single reading, the Arduino can collect multiple readings and select the median value. This helps reject occasional extreme or incorrect readings. 


// Read the input three times.
readings = [read(), read(), read()]

// Find the middle value.
value = median(readings)

// Use the filtered value.
use(value)

For example, if three readings are 100, 101, and 900, the median is 101. The incorrect reading of 900 does not significantly affect the result. For digital switches, a similar idea can be implemented through repeated sampling and majority voting.

Q3. Addressing Sensor Noise

If an input device produces readings that randomly fluctuate by approximately 10%, one possible solution is to average multiple measurements. Averaging can reduce random fluctuations because positive and negative errors may partially cancel each other. 


// Initialize the sum.
sum = 0

// Collect N sensor readings.
for i in 1..N:
    // Add each reading to the sum.
    sum += read()

// Calculate the average measurement.
value = sum / N

// Use the smoothed measurement.
use(value)

This approach is useful for reducing random measurement noise. However, averaging does not necessarily correct consistent measurement errors or sensor bias.
